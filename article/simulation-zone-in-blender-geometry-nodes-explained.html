Simulation Zone in Blender Geometry Nodes Explained

The Simulation Zone in Blender Geometry Nodes is a specialized node framework that allows artists to build dynamic, iterative, and physics-based simulations directly within the Geometry Nodes modifier. Unlike standard nodes that evaluate states independently per frame, the Simulation Zone carries data forward from one frame to the next. This enables the creation of custom particle systems, fluid-like behaviors, generative growth effects, and interactive animations natively in Blender.

How the Simulation Zone Works

At the core of the Simulation Zone is a feedback loop created between two linked nodes: the Simulation Input node and the Simulation Output node.

In a standard Geometry Node tree, calculations are static relative to time; the node network evaluates the current frame purely based on current input parameters. The Simulation Zone alters this behavior:

  1. Initial State (Frame 1): The geometry and attributes plugged into the outside of the Simulation Input node act as the starting condition.
  2. Evaluation: The nodes placed inside the zone apply transformations, vector math, force calculations, or instancing logic to the geometry.
  3. State Transfer: The processed geometry reaches the Simulation Output node, which writes the state for that frame.
  4. Iterative Loop (Frame N+1): On the subsequent frame, the Simulation Input node reads the output from the previous frame rather than recalculating from the initial state.

Key Components

  • Delta Time Socket: Located on the Simulation Input node, this output provides the exact elapsed time between frames in seconds, allowing for frame-rate-independent physics calculations.
  • Custom Data Sockets: Users can add custom data types (such as Floats, Integers, Vectors, Colors, and Booleans) to the Simulation Input and Output nodes. This allows custom attributes, such as velocity, age, mass, or health, to persist and evolve across frames.
  • Bake Controls: Simulation zones require continuous frame-by-frame evaluation. The modifier interface and physics cache settings allow users to bake the simulation to memory or disk to ensure stable playback and render performance.

Common Use Cases

  • Procedural Particle Systems: Emitting, moving, and destroying particles based on custom forces, collisions, and lifespan logic without using the legacy particle system.
  • Organic Growth: Simulating branching trees, spreading vines, slime molds, or cellular automata by instancing geometry that expands on each iteration.
  • Custom Physics and Flocking: Simulating boids algorithms (bird/fish schooling), simple cloth physics, or trail effects by applying directional forces and distance constraints.

By maintaining state over time, the Simulation Zone transforms Geometry Nodes from a static modeling and scattering system into a fully procedural animation and dynamics engine.
