How to Use Repeat Zone in Blender Geometry Nodes

The Repeat Zone in Blender Geometry Nodes is an iterative processing tool that allows you to execute a specific set of nodes multiple times in a loop. By passing data through repeated cycles, it enables dynamic simulations, recursive procedural modeling, and complex transformations without requiring repetitive, manually chained node setups.

What is the Repeat Zone?

Introduced in Blender 4.0, the Repeat Zone consists of two paired nodes: the Repeat Input and the Repeat Output. Any geometry, vector, integer, float, or boolean data plugged into the input node is processed through the nodes placed inside the zone and then fed back into the next iteration until the specified count is reached.

How It Works

  1. Iterations Control: The Repeat Input node features an Iterations value, which defines the total number of times the enclosed operation will execute. Setting this to zero bypasses the operation entirely.
  2. Data Accumulation: Unlike simple instance scattering, each cycle in the Repeat Zone can read the result of the previous cycle. This allows modifications—such as translations, rotations, or scale changes—to compound over time.
  3. Custom Sockets: You can add custom data sockets (such as transforms, seed integers, or math values) to pass and modify non-geometric variables alongside the geometry itself.

Common Use Cases

  • Recursive and Fractal Geometry: Creating self-similar structures like trees, branching root networks, snowflakes, and Sierpinski-style fractals where geometry subdivides and branches systematically.
  • Progressive Transformations: Building spiral staircases, coiled springs, cables, or overlapping chain links where each element requires an incremental offset based on the position of the previous element.
  • Algorithmic Modeling: Iterative mesh operations, such as progressive smoothing, step-by-step mesh extrusion, or selective vertex displacement over a set number of passes.
  • Lightweight Custom Simulations: Running iterative math algorithms for particle motion, procedural growth over time, or simple physics-like pathfinding without the overhead of the dedicated Simulation Zone.

Advantages

Before the Repeat Zone, creating repetitive logic required duplicating node groups multiple times, leading to cluttered node trees and fixed, unchangeable loop counts. The Repeat Zone cleans up complex node graphs, optimizes memory, and allows loop counts to be exposed as dynamic parameters in the modifier stack.
