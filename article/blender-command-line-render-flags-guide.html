Blender Command Line Render Flags Guide

Rendering Blender projects headlessly via the terminal allows you to bypass the graphical user interface (GUI), maximizing CPU and GPU performance while reducing system memory overhead. This guide details the essential command-line flags needed to initiate headless rendering, customize output paths, configure render engines, and specify single frames or animation sequences.

The Essential Headless Flags

To render without launching the GUI, Blender requires a minimal command structure containing the background execution flag and a render action flag.

1. Background Mode Flag (-b or --background)

The -b flag is the core requirement for headless rendering. It instructs Blender to launch purely within the terminal environment without opening any windows or graphical context. This flag must precede the target .blend file path or come immediately after it.

2. Execution Flags (-f or -a)

Blender needs an explicit instruction determining whether to render a single frame or an entire sequence:

  • -f <frame_number> (--render-frame <frame_number>): Renders a specific single frame. You can also specify relative frames (e.g., -f +1 for the next frame) or comma-separated lists (e.g., -f 1,5,10).
  • -a (--render-anim): Renders the complete animation sequence defined in the project settings or constrained by start/end flags.

Basic Command Examples

Render a single frame (Frame 1):

blender -b project.blend -f 1

Render an entire animation:

blender -b project.blend -a

Important Flags for Headless Configuration

When running Blender on remote servers or render farms, default project settings often need to be overridden dynamically via the terminal.

Output Management

  • -o <path> (--render-output <path>): Defines the target directory and file naming scheme. Using // sets the path relative to the .blend file. Use # characters as frame padding placeholders (e.g., -o //render_#### produces render_0001.png).
  • -F <format> (--render-format <format>): Overrides the output file format. Common options include PNG, JPEG, OPEN_EXR, OPEN_EXR_MULTILAYER, and FFMPEG.

Frame Range Control

  • -s <frame> (--frame-start <frame>): Defines the start frame for an animation sequence.
  • -e <frame> (--frame-end <frame>): Defines the end frame for an animation sequence.
  • -j <step> (--frame-jump <step>): Sets the frame stepping increment (e.g., -j 2 renders every second frame).

Engine and Hardware Control

  • -E <engine> (--engine <engine>): Specifies the render engine. Values include CYCLES, BLENDER_EEVEE_NEXT, or BLENDER_WORKBENCH.
  • -t <threads> (--threads <threads>): Sets the maximum number of CPU worker threads used during the render process.

Advanced Command Example

The following command runs Blender headlessly, overrides the render engine to Cycles, sets a custom frame range from 10 to 50, changes the output path to a dedicated directory, and renders the animation:

blender -b scene.blend -E CYCLES -o /renders/frame_#### -F PNG -s 10 -e 50 -a

Note: In Blender CLI syntax, the order of flags matters. Flags that modify render settings (like -o, -s, -e, and -E) must be placed before the execution flags (-f or -a).
